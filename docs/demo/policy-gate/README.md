# Evidence: OPA policy gate (scenario #4, attack blocked)

This directory holds **captured evidence** that LoonVault's pre-deploy OPA/conftest policy gate
blocks a non-compliant change: the attack-and-defense "crown jewel" (`plan.md` scenario #4).

Generated by `demo/policy-gate/run.sh` (see that directory's README). Re-run it to refresh.

## Files
| File | What it shows |
|---|---|
| `bad-gate-output.txt` | The gate **denying** the insecure plan (open SSH + public S3), with control-tagged messages |
| `bad-report.json` | The per-run validation artifact (`"result": "fail"`), audit evidence |
| `good-gate-output.txt` | The gate **passing** the compliant plan |
| `good-report.json` | The per-run validation artifact (`"result": "pass"`) |

The JSON artifacts carry the run metadata (timestamp, stack, git commit, **policy version** =
git tree-sha of `policies/`, tool version), the evaluated scope, the pass/fail result, and the raw
conftest output: so each verdict is pinned to the exact policy set that produced it.

## Why this matters
- **Security:** demonstrates the preventive control stopping a real misconfiguration before deploy.
- **Compliance-as-code:** the `fail` artifact is literal evidence that a non-compliant change was
  caught and recorded, mapped to an OSFI B-13 principle / GC Cloud Guardrail.

These are the committed, curated demo copies; live per-run reports in `policy-reports/` are
git-ignored.
