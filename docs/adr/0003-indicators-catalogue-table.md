# Indicators catalogue table introduced in Phase 1

The RDS schema includes an `indicators` catalogue table (columns: `code`, `kind`, `label`) that `series_observations` references by FK, even though Phase 1 only ingests one Series. The alternative was a single flat `series_observations` table with no catalogue, deferring the FK until Phase 2. We chose to introduce the catalogue in Phase 1 because the schema would otherwise have no table that represents the domain concept of an Indicator: the umbrella term for everything the public API exposes. Deferring would have required a Phase 2 migration (add table, backfill, add FK constraint) on a schema that was already in use, and would have left Phase 1 interviews with a schema that contradicts the documented domain language.
