# Single CMK shared across Phase 1 encrypted resources

All Phase 1 resources that require encryption at rest with a customer-managed key (S3 raw zone, RDS, and Secrets Manager) share a single KMS CMK. The S3 snapshots bucket is an exception: it uses SSE-S3 (AES-256) because it is publicly readable via Cloudflare, and anonymous S3 requests cannot decrypt SSE-KMS objects, they have no IAM identity with which to call kms:Decrypt. The Phase 0 Terraform state CMK remains separate as it belongs to a different lifecycle and module. The alternative, a dedicated CMK per service, would cost an additional $2/month ($1/CMK/month × 2 extra keys) for no functional difference in a single-developer project. The tradeoff is blast radius: if this CMK is disabled, scheduled for deletion, or its key policy is misconfigured, all Phase 1 encrypted data becomes inaccessible simultaneously rather than one service at a time. This is accepted for the POC given the budget constraint and single-account, single-developer operating model. In a production financial institution deployment, separate CMKs per service (or per data classification tier) would be required to contain the impact of key lifecycle events and to satisfy audit requirements for per-service key policies.
