# S3 snapshots written by Transform Lambda for frontend resilience

After each successful RDS write, the Transform Lambda also writes a pre-computed JSON snapshot of the Series (and, in Phase 2, Pressure Metrics) to a dedicated S3 snapshots bucket. The frontend calls the live API first; if the API is unavailable, it falls back to the S3 snapshot served through Cloudflare. The alternative was to accept a broken Data Analysis section whenever the ephemeral backend is destroyed, or to make the frontend read exclusively from S3 (bypassing the API entirely). The API-first-with-S3-fallback approach was chosen because the live API query must remain demonstrable for the portfolio, while the always-on frontend must still show real data between interview deployments. The snapshot data is public-readable by design: it is the same data already served by the public API, and Cloudflare proxies the snapshots bucket under the same domain.
