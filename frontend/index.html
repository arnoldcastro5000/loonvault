Cloud-security portfolio · OSFI B-13

Bank-grade security for a public data API

A public API serving Bank of Canada cost-of-living indicators, built and secured the way a Canadian financial institution would: defense-in-depth, a STRIDE threat model, and live attack-and-defense demonstrations.

The data is payload, not the point. The indicators exist to justify real infrastructure worth securing. All the engineering effort is the security story.

Security highlights

Identity

Tiered access; admin plane behind Cloudflare Access (Zero-Trust + MFA) with the CF Access JWT validated at the origin. Least-privilege IAM per Lambda.

Secrets / DB auth

RDS IAM authentication: application DB users have no stored credential; SigV4 tokens, 15-minute TTL.

Network

Private subnets, security-group-to-security-group ingress only (no CIDR), gateway VPC endpoints (no NAT), VPC Flow Logs.

Data

Customer-managed KMS on S3, RDS & Secrets Manager; TLS 1.2 at every hop; S3 Block Public Access on private buckets.

Guardrail & audit

Region-lock SCP pins workloads to ca-central-1; a tamper-evident organization-wide CloudTrail.

Policy-as-code

An OPA gate blocks insecure Terraform before deploy; the OSFI/GC compliance matrix is generated from the policy metadata. See the compliance matrix.

Architecture

  • Edge (Cloudflare): DNS · WAF · rate-limit · TLS Full-strict · Access (MFA) for /admin
  • Public read → API Gateway (HTTP API) → Lambda authorizer (origin secret + CF Access JWT) → Read Lambda (in VPC)
  • Data → RDS Postgres in private subnets (IAM auth · CMK · TLS verify-full)
  • Ingest → EventBridge (daily) → Ingest Lambda → S3 raw zone (CMK) → Transform Lambda → RDS + public S3 snapshots
  • This site: always-on static frontend; falls back to public snapshots when the API is down

Ephemeral backend (terraform apply for demos, destroy after); always-on frontend. Everything in ca-central-1, all Terraform.
