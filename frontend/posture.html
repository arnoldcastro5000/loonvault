Security posture

Threat-led, not checklist-led: every control traces to a threat in the model.

Threat model (STRIDE + DREAD)

A full threat model drives the design: threat-actor profiles, architecture trust boundaries, a DREAD-scored threat catalogue, ranked threats, control gaps, accepted residual risks, and a STRIDE coverage matrix. Source: docs/threat-model.md.

Defense-in-depth controls

Identity & access

Cloudflare Access (Zero-Trust + MFA); CF Access JWT validated at the origin; least-privilege IAM role per Lambda; credential-free CI.

Data at rest

Customer-managed KMS on S3 raw zone, RDS, Secrets Manager; annual key rotation; S3 Block Public Access on private buckets.

Data in transit

TLS 1.2 at every hop; Cloudflare Full-strict; sslmode=verify-full to RDS.

Infrastructure

VPC private subnets; SG-to-SG ingress only; gateway VPC endpoints; region-lock SCP at a Workloads OU.

Threat & vuln mgmt

OPA policy gate + Checkov + Semgrep; gitleaks / betterleaks / TruffleHog; SHA-pinned Actions; Dependabot; Prowler post-deploy.

Monitoring & response

Organization-wide CloudTrail (management + data events); EventBridge → CloudWatch → SNS detection.

AI-assisted development

This repo is built with an AI coding agent. The primary risk — prompt injection turning the agent into a confused deputy — is treated explicitly (threat T-051): the agent runs in a sandboxed devcontainer with an egress allowlist and no AWS credentials, and all AI-generated Terraform passes the same OPA gate and CI scans as human-written code, regardless of authorship.
